# CASINO ACADEMY — בלאק ג'ק ובאקרה בעברית

אפליקציית מובייל אחת לשני משחקי קזינו, בעברית מלאה עם RTL, שעובדת גם ללא אינטרנט:

**🃏 BLACKJACK** — משחק אמיתי, קורס בן 15 פרקים, אימון אסטרטגיה בסיסית, ספירת קלפים
Hi-Lo, ספירה אמיתית, הערכת חפיסות, פריסת הימורים, סימולציית קזינו (כולל מצב מתקדם ללא
ספירה על המסך), אימון סטיות, סימולטור מונטה קרלו ומחשבון סיכון חורבן.

**♦️ BACCARAT** — שולחן מלא עם לוחות תוצאות, קורס מדורג בן 14 פרקים, מאמן חוקי הקלף
השלישי, מאמן חישוב יד, מאמן יד מלאה, מאמן קריאת לוחות, מסך הסתברויות ויתרון בית,
מודול מעקב וכשלים לוגיים, סימולטור מונטה קרלו וסימולציית מפגש.

לכל משחק יש עולם עצמאי: משחק, לימוד, אימונים, סימולציות, סטטיסטיקות והתקדמות.

## הפעלה

```bash
cd blackjack-master
npm run build     # קומפילציה של TypeScript אל ../blackjack/js
npm run serve     # שרת מקומי על http://localhost:4173
npm test          # 126 בדיקות מנוע, מתמטיקה ותוכן
npm run typecheck # בדיקת טיפוסים מלאה
```

התיקייה `blackjack/` בשורש המאגר היא האפליקציה המוכנה לפרסום (כולל הקוד הבנוי),
ולכן GitHub Pages מגיש אותה ישירות תחת `/blackjack/` — בלי שלב בנייה בשרת.

**בטלפון:** פתיחת הכתובת בדפדפן ← תפריט השיתוף ← "הוסף למסך הבית"
(iPhone: Safari · Android: Chrome). מכאן האפליקציה נפתחת במסך מלא, בלי סרגלי
דפדפן, ועובדת גם ללא אינטרנט.

## למה PWA ולא React Native / Expo

הדרישה המקורית הייתה React Native + Expo. בסביבת הפיתוח שבה נבנה הפרויקט רישום
ה-npm חסום לחלוטין (‎403 על כל חבילה, כולל `expo` ו-`react-native`), ולכן אי אפשר
היה להתקין, לבנות או להריץ פרויקט Expo — וממילא לא לעמוד בדרישה "מוצר עובד, לא דמו".

הפתרון שנבחר הוא ה-Stack המקצועי היחיד שמאפשר מוצר מובייל מלא בסביבה הזו:

* **TypeScript** במצב `strict` — כל הקוד, כולל המנוע המתמטי.
* **PWA** — אפליקציה שמותקנת ב-iPhone וב-Android ממש כמו אפליקציה מחנות,
  עם `manifest`, אייקונים, מסך מלא, Service Worker ועבודה לא מקוונת.
* **אפס תלויות זמן ריצה** — ללא ספריות חיצוניות: ניהול מצב, ניתוב, רכיבים,
  גרפים, צלילים ואנימציות נכתבו בפרויקט. לכן אין שלב Bundler ואין `node_modules`.
* **Web Worker** לסימולציות כבדות (מיליון ידיים ללא הקפאת ממשק).
* **בדיקות** עם מריץ הבדיקות המובנה של Node (`node --test`) ישירות על קבצי TypeScript.

## המתמטיקה — ומה מאומת מול מה

האפליקציה לא מציגה מספרים "מהזיכרון". כל מספר מחושב מהחוקים שנבחרו:

* **טבלאות אסטרטגיה בסיסית** נבנות על ידי מנוע ה-EV: לכל יד מול כל קלף דילר
  מחושבות תוחלות עמידה / לקיחה / הכפלה / פיצול / כניעה, והתא מקבל את הפעולה
  בעלת התוחלת הגבוהה ביותר. הבדיקות מוודאות שהטבלה שנוצרת עבור 6 חפיסות
  (S17 ו-H17, עם ובלי DAS, עם ובלי כניעה) **זהה לטבלאות האסטרטגיה הבסיסית המקובלות**.
* **יתרון הבית** מחושב אנליטית על כל צירופי הקלפים. התוצאות: 0.38% עבור
  6 חפיסות S17 DAS עם כניעה, 0.59% ל-H17, 1.95% בתשלום 6:5 — בתחום של פחות
  מ-0.03% מהערכים המפורסמים.
* **הסימולטור** מריץ את מנוע המשחק האמיתי. באימות מול החישוב האנליטי (חלוקה
  מנעל טרייה בכל סיבוב) הפער היה בתוך רווח הסמך של 95%.
* **סיכון חורבן** מחושב בקירוב תנועה בראונית; ההנחות מוצגות במסך עצמו.

### באקרה

* **ההסתברויות** מחושבות במעבר על כל צירופי הקלפים האפשריים בסיבוב, עם שקלול מדויק
  ללא החזרה ויישום מלא של חוקי הקלף השלישי. התוצאה ל-8 חפיסות: בנקאי 45.8597%,
  שחקן 44.6247%, תיקו 9.5156% — זהה לערכים המפורסמים.
* **יתרון הבית** נגזר מההסתברויות ומחוקי התשלום שנבחרו: בנקאי 1.0579%, שחקן 1.2351%,
  תיקו 8:1 → 14.3596%, תיקו 9:1 → 4.8440%, וללא עמלה (בנקאי עם 6 משלם חצי) → 1.4581%.
* **הסימולטור** מריץ את מנוע המשחק עצמו, ותוצאותיו מתלכדות עם החישוב המדויק בתוך
  רווח הסמך הסטטיסטי.
* **חוקי הקלף השלישי** ממומשים לפי Punto Banco ומכוסים בבדיקות יחידה לכל שורה בטבלה.

### הנחות והבהרות שמוצגות גם באפליקציה

1. בעץ החישוב התפלגות הקלפים נלקחת מהנעל לאחר הסרת הקלפים הידועים ומוחזקת קבועה
   (דגימה עם החזרה) — הקירוב הסטנדרטי לאסטרטגיה תלוית־סכום. בחפיסה אחת ייתכנו
   הבדלים קטנים מטבלאות תלויות־הרכב.
2. תוחלת הפיצול מחושבת כפעמיים תוחלת יד בודדת לאחר פיצול, ללא פיצול חוזר.
3. מספרי האינדקס לסטיות (Illustrious 18, Fab 4) מתועדים ומיועדים לנעל של
   4-8 חפיסות; במשחק חפיסה אחת או שתיים האפליקציה מציינת זאת במפורש.
4. הקירוב "0.5% לכל נקודת ספירה" מוצג ככזה, לצד חישוב EV מהרכב נעל מותאם ספירה.
5. בבאקרה מוצגים שני לוחות התוצאות הבסיסיים — לוח החרוזים (Bead Plate) והדרך הגדולה
   (Big Road) — שחוקיהם ממומשים במדויק. הלוחות הנגזרים (Big Eye Boy, Small Road,
   Cockroach Pig) אינם מוצגים, והאפליקציה מסבירה זאת במפורש במקום להציג חוקים
   שאינה יכולה לאמת. גם הם, ממילא, אינם מספקים מידע על היד הבאה.

## הפרדה בין המשחקים

מודול הבאקרה עצמאי: מנוע, תוכן, מסכים ומצב משלו תחת `src/baccarat/`. מצב הבאקרה
נשמר כמפתח נפרד, כך שמצבים שנשמרו לפני הוספת המודול ממשיכים לעבוד ונתוני הבלאק ג'ק
אינם מושפעים. בדיקות ייעודיות מוודאות זאת בשני הכיוונים, כולל איפוס נפרד לכל משחק.
הרכיבים המשותפים הם תשתית בלבד: קלפים, נעל, RNG, סטטיסטיקה, רכיבי UI וניתוב.

## משחק אחראי

האפליקציה היא כלי לימוד וסימולציה. אין בה כסף אמיתי. גם אסטרטגיה נכונה וספירת
קלפים אינן מבטיחות ניצחון, ובאקרה הוא משחק מזל שבו אין שיטה שהופכת את יתרון הבית
לחיובי. תוצאות קצרות טווח יכולות להיות שונות מאוד מהתוחלת המתמטית. מסכים ייעודיים
באפליקציה מסבירים זאת, וכל מסך סימולציה מציג את ההסתייגות.
